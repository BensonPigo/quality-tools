# 補充：認知複雜度（Cognitive Complexity）

> 建議先讀 `補充_圈複雜度.md`。

圈複雜度量的是「要寫幾筆測試」，認知複雜度量的是「讀懂這段程式要花多少腦力」。後者由 SonarSource 的 G. Ann Campbell 在 2017 年提出，目的是補上圈複雜度的盲點：

| 函式 | 圈複雜度 | 認知複雜度 | 實際閱讀難度 |
|---|---|---|---|
| 查表式 `switch`，5 個 `case` 各回傳一個字串 | 6 | **1** | 很容易 |
| 三個並排的 `if` | 4 | **3** | 容易 |
| 三層巢狀的 `if` | 4 | **6** | 難 |

圈複雜度把這三種情況評得差不多，認知複雜度的排序則和人實際讀起來的感受一致。

> 本文件的分數都用 gocognit v1.3.0 實際跑過。

## 一、三條基本原則

1. **打斷由上往下閱讀的結構，加 1。** 例如 `if`、`for`、`switch`。讀到這裡，讀者要開始分岔思考。
2. **巢狀越深，加越多。** 在第二層的 `if` 比在第一層的 `if` 難懂，因為讀者要同時記住外層的條件。
3. **讓程式更好讀的寫法不加分。** 例如一整個 `switch` 只算一次，不管有幾個 `case`；同一種邏輯運算子連在一起，也只算一次。

## 二、計分規則（gocognit）

以下整理自 gocognit 原始碼：

| 結構 | 基本分 | 巢狀加分 | 說明 |
|---|---|---|---|
| `if` | +1 | ✅ | |
| `else if` | +1 | ❌ | 和 `if` 同一層，不算巢狀 |
| `else` | +1 | ❌ | 圈複雜度不算 `else`，認知複雜度要算 |
| `switch`、`select` | +1 | ✅ | **整個 `switch` 只算一次**，`case` 不加分 |
| `for`、`for range` | +1 | ✅ | |
| 邏輯運算子序列 | 每換一種運算子 +1 | ❌ | `a && b && c` 算 1；`a && b \|\| c` 算 2 |
| 帶標籤的 `break`、`continue`、`goto` | +1 | ❌ | 一般的 `break`、`continue` 不加分 |
| 遞迴呼叫 | +1 | ❌ | |

**「巢狀加分」的意思**：除了基本分 1，再加上它目前所在的巢狀層數。最外層是 0 層，所以最外層的 `if` 得 1 分；包在一個 `if` 裡面的 `if` 得 1 + 1 = 2 分；再包一層就得 1 + 2 = 3 分。

會讓巢狀層數加 1 的位置：`if`／`else` 的區塊、`switch`、`select`、`for` 的區塊，以及匿名函式（`func() { ... }`）。匿名函式本身不加分，但裡面的結構會多一層。

## 三、範例

### 巢狀 vs 並排

```go
// 三層巢狀：認知複雜度 6
if a {          // +1（第 0 層）
	if b {      // +2（第 1 層：1 + 1）
		if c {  // +3（第 2 層：1 + 2）
```

```go
// 三個並排：認知複雜度 3
if a { n++ }    // +1
if b { n++ }    // +1
if c { n++ }    // +1
```

圈複雜度兩者都是 4。

### 查表式 switch

```go
switch level {   // +1，整個 switch 只算一次
case 0:
	return "非會員"
case 1:
	return "會員"
// ...共 5 個 case 加 default
}
```

認知複雜度 1，圈複雜度 6。讀這種程式不需要記住任何狀態，認知複雜度給 1 比較貼近事實。

### 邏輯運算子

```go
return a && b && c   // 認知 1：同一種運算子連在一起，讀起來是一句話
return a && b || c   // 認知 2：混用兩種運算子，要停下來想優先順序
```

圈複雜度兩者都是 3。

### if / else if / else

```go
if score >= 90 {        // +1
	return "A"
} else if score >= 80 { // +1
	return "B"
} else {                // +1
	return "C"
}
```

認知複雜度 3，圈複雜度 3。兩者剛好相等，但算法不同：圈複雜度不算 `else`，認知複雜度要算。

### 遞迴

```go
func Factorial(n int) int {
	if n <= 1 {                  // +1
		return 1
	}
	return n * Factorial(n-1)    // +1，遞迴
}
```

認知複雜度 2。讀遞迴需要在腦中展開呼叫過程，所以要加分。

## 四、實際算一次：`Checkout` 的認知複雜度是 17

```go
func Checkout(...) int {
	if len(items) == 0 {                                       // +1（第 0 層）       → 1
	for _, it := range items {                                 // +1（第 0 層）       → 2
		if it.Qty <= 0 {                                       // +2（第 1 層）       → 4
		if !it.OnSale {                                        // +2（第 1 層）       → 6
			if level == Member {                               // +3（第 2 層）       → 9
			} else if level == VIP {                           // +1（else if 不加巢狀）→ 10
	if coupon == "SAVE100" && total >= 1000 {                  // if +1、&& +1        → 12
	if total >= 3000 {                                         // +1                  → 13
	if total < 1000 && level != VIP && coupon != "FREESHIP" {  // if +1、&& 序列 +1   → 15
		if coupon == "HALFSHIP" {                              // +2（第 1 層）       → 17
```

圈複雜度是 14，認知複雜度是 17。差距主要來自 `for` 裡面那幾層巢狀的 `if`：會員折扣的判斷包在 `for` 和 `if !it.OnSale` 兩層裡面，光這一個 `if` 就得 3 分。

注意倒數第二行：`&& ... && ...` 有兩個 `&&`，圈複雜度加 2，認知複雜度只加 1，因為同一種運算子連在一起只算一次。

## 五、怎麼降低認知複雜度

### 1. 提早 return（Guard Clause）

最有效的方法。把「不符合條件就離開」的判斷放在最前面，主要邏輯就不用一層一層往內縮：

```go
// 巢狀版
func CanCheckout(loggedIn, hasItems, inStock bool) bool {
	if loggedIn {
		if hasItems {
			if inStock {
				return true
			}
		}
	}
	return false
}
```

```go
// 提早 return 版
func CanCheckout(loggedIn, hasItems, inStock bool) bool {
	if !loggedIn {
		return false
	}
	if !hasItems {
		return false
	}
	if !inStock {
		return false
	}
	return true
}
```

兩版的圈複雜度都是 4，認知複雜度從 6 降到 3。這種改寫**不會減少分岔數**，所以 CRAP 分數不會變，但程式明顯好讀很多。

### 2. 拆函式

把內層邏輯抽成獨立函式，巢狀層數歸零。`README.md` 練習 3 把 `Checkout` 拆成七個小函式，就是在做這件事。

### 3. 不要混用 `&&` 和 `||`

`a && b || c` 這種寫法，讀者要停下來想運算子的優先順序。改成具名變數，讀起來更清楚：

```go
isEligible := a && b
return isEligible || c
```

這樣改分數不會變（兩個運算子序列各算 1，總共還是 2），gocognit 也看不出差別。不過具名變數把「這個條件代表什麼」寫了出來，可讀性確實有提升。分數只是參考，最後還是要回到「人讀不讀得懂」。

## 六、和 CRAP 的關係

CRAP 公式用的是圈複雜度，**不要直接把認知複雜度代進去。** CRAP 的邏輯是「分岔越多，越需要測試覆蓋」，這個推論建立在「圈複雜度 ≈ 最少測試數」上。認知複雜度量的是可讀性，跟需要幾筆測試沒有直接關係。

建議的做法是把兩者當成**兩道獨立的閘門**：

| 閘門 | 量什麼 | 擋下什麼 |
|---|---|---|
| CRAP（圈複雜度 + 覆蓋率） | 測試風險 | 分岔多、測試少的函式 |
| 認知複雜度 | 可讀性 | 巢狀太深、邏輯糾結的函式 |

以 AI 代理人開發來說，認知複雜度這道閘門特別有用：AI 很容易寫出一層包一層的 `if`，測試全綠、CRAP 也過了，但人類簽核時根本看不懂。SonarQube 的預設門檻是 15，可以從這個數字開始。

### 執行方式

```bash
# 列出正式程式碼每個函式的認知複雜度
go run github.com/uudashr/gocognit/cmd/gocognit@v1.3.0 -ignore "_test|tools" .

# 只列出超過 15 的函式（有超過時結束碼為 1，可以放進 CI）
go run github.com/uudashr/gocognit/cmd/gocognit@v1.3.0 -ignore "_test|tools" -over 15 .
```

gocognit 預設會把測試檔一起算進去，`-ignore "_test|tools"` 用來排除測試檔和 `tools/crap` 量測工具，只看正式程式碼。gocognit v1.3.0 需要 Go 1.24 以上。
