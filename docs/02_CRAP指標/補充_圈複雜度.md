# 補充：圈複雜度（Cyclomatic Complexity）

> 搭配 `README.md` 閱讀。CRAP 公式裡的 C 就是圈複雜度。

圈複雜度是函式裡「獨立路徑」的數量，可以把它理解成：**要讓每個分岔都至少走過一次，最少需要幾筆測試。**

## 一、原始定義：畫流程圖

圈複雜度由 Thomas McCabe 在 1976 年提出。做法是把函式畫成流程圖，每個步驟是一個節點，步驟之間的走向是一條邊：

$$
M = E - N + 2
$$

E 是邊數，N 是節點數。（完整公式是 $E - N + 2P$，P 是互不相連的圖的數量，一個函式就是 1。）

以 `applyThresholdRebate` 為例：

```go
func applyThresholdRebate(total int) int {
	if total >= 3000 {
		return total - 300
	}
	return total
}
```

```
        [開始]
           │
   (total >= 3000?)
      ╱         ╲
    是           否
    │             │
[減 300]          │
      ╲         ╱
        [結束]
```

節點 4 個（開始、判斷、減 300、結束），邊 4 條，M = 4 − 4 + 2 = **2**，也就是「有折」和「沒折」兩條路。

## 二、實務算法：數關鍵字

每個函式都畫圖太費工，實務上用這條捷徑，結果和畫圖一樣：

> **圈複雜度 = 1 + 判斷點的數量**

本專案使用的 gocyclo（v0.6.0）原始碼裡，判斷點的規則只有這些：

| 加 1 | 不加 |
|---|---|
| `if`（包含 `else if`，它本身就是一個新的 `if`） | `else` |
| `for`、`for range` | `switch`、`select` 本身 |
| `switch` 中每個有列出值的 `case` 子句 | `default` |
| `select` 中每個有列出通道操作的 `case` 子句 | `select` 的 `default` |
| `&&`、`\|\|` | `return`、`continue`、`break`、函式呼叫 |

### 為什麼 `&&`、`||` 也要算

Go 的 `&&`、`||` 會短路求值：前半段就能決定結果時，後半段根本不會執行。

```go
if coupon == "SAVE100" && total >= 1000 {
```

只有一個 `if`，卻有三條路：

1. 優惠券不是 SAVE100 → 不折（`total >= 1000` 沒有被檢查）
2. 優惠券是 SAVE100，金額未滿 1000 → 不折
3. 兩者都符合 → 折 100

程式在兩個地方分岔，所以這行加 2。

### 多值 `case` 只算 1

```go
switch x.Type {
case "A", "B":   // gocyclo 只加 1
```

gocyclo 以「一個 `case` 子句」為單位計算，不管裡面列了幾個值。但 `case "A", "B"` 的邏輯等同於 `x.Type == "A" || x.Type == "B"`，改寫成 `if` 就會變成加 2。有些工具會把每個值都算 1，所以：

> **圈複雜度只能在同一套工具內互相比較。** CRAP 門檻是在某套工具上定出來的，換工具或升級工具版本，門檻都要重新校準。本專案把 gocyclo 鎖在 `go.mod` 的 v0.6.0，原因之一就是這個。

## 三、實際算一次：`Checkout` 為什麼是 14

```go
func Checkout(...) int {                                       // 起始值 1
	if len(items) == 0 {                                       // +1 → 2
	for _, it := range items {                                 // +1 → 3
		if it.Qty <= 0 {                                       // +1 → 4
		if !it.OnSale {                                        // +1 → 5
			if level == Member {                               // +1 → 6
			} else if level == VIP {                           // +1 → 7
	if coupon == "SAVE100" && total >= 1000 {                  // if +1、&& +1 → 9
	if total >= 3000 {                                         // +1 → 10
	if total < 1000 && level != VIP && coupon != "FREESHIP" {  // if +1、&& +2 → 13
		if coupon == "HALFSHIP" {                              // +1 → 14
```

和 `go run ./tools/crap` 顯示的 14 一致。

## 四、這個數字代表什麼

### 最少測試數，不是全部路徑數

`Checkout` 有好幾個彼此獨立的判斷，全部排列組合起來的路徑有好幾百條。圈複雜度 14 指的是：設計得當的話，大約 14 筆測試就能讓每個分岔都至少走一次。

以這段程式為例（圈複雜度 5）：

```go
if a > 0 && b > 0 { ... } else if c == 1 || d == 2 { ... }
```

| # | 輸入 | 走的路 |
|---|---|---|
| 1 | a > 0、b > 0 | 第一個 `if` 成立 |
| 2 | a ≤ 0 | `&&` 第一個條件就不成立，b 沒被檢查 |
| 3 | a > 0、b ≤ 0 | `&&` 第二個條件不成立 |
| 4 | 第一個 `if` 不成立、c == 1 | `\|\|` 第一個條件成立，d 沒被檢查 |
| 5 | 第一個 `if` 不成立、c ≠ 1、d == 2 | `\|\|` 第二個條件成立 |

「兩個 `if` 都不成立」這條路不用另外寫一筆：第 2、3 筆只要順便讓 c ≠ 1、d ≠ 2 就走到了。

### 為什麼 CRAP 用它代表風險

- **越難測**：需要的測試越多，越容易漏掉某個分岔。
- **越難改**：修改時要同時顧到越多條路，AI 代理人越容易「改 A 壞 B」。

McCabe 當初建議一個函式的圈複雜度不要超過 10。gocyclo 可以直接列出超過某個值的函式：

```bash
go run github.com/fzipp/gocyclo/cmd/gocyclo@v0.6.0 -over 10 .
```

## 五、盲點

圈複雜度只數分岔，不管程式好不好讀：

| 情況 | 圈複雜度 | 實際閱讀難度 |
|---|---|---|
| 查表式 `switch`，5 個 `case` 各回傳一個字串 | 6 | 很容易，一眼看完 |
| 三個並排的 `if` | 4 | 容易 |
| 三層巢狀的 `if` | 4 | 難，要同時記住三個條件 |

後兩者分數一樣，閱讀難度卻差很多。這個盲點就是「認知複雜度」要解決的問題，請接著讀 `補充_認知複雜度.md`。

## 練習

算出以下兩段程式的圈複雜度（以 gocyclo 的規則計算）。

**第 1 題**

```go
if a > 0 && b > 0 { ... } else if c == 1 || d == 2 { ... }
```

**第 2 題**

```go
for _, x := range items {
	switch x.Type {
	case "A", "B":
		total += x.Price
	case "C":
		if x.Price > 100 {
			total += 100
		}
	default:
		continue
	}
}
```

<details>
<summary>答案</summary>

**第 1 題：5**

起始 1 + `if` 1 + `&&` 1 + `else if` 1 + `||` 1 = 5。只數 `if`、`else if` 會得到 3，這是最常見的錯誤。

**第 2 題：5**

起始 1 + `for range` 1 + `case "A", "B"` 1 + `case "C"` 1 + `if` 1 = 5。`switch`、`default`、`continue` 都不加分。把 `"A"`、`"B"` 各算 1 會得到 6，但 gocyclo 以 `case` 子句為單位，只算 1。

</details>
